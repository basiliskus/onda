## Where we were

v0.4.0 — the `:app` test harness, song capture, cross-playlist move — was
complete, reviewed, retro'd, and **invisible**. `versionName` was still `0.3.0`
and the newest GitHub release was `v0.3.0` (2026-07-24). Nothing from the
milestone had ever run on the phone.

That single fact blocked three separate things:

- the ten owed hardware smoke rows (GitHub #33),
- the first real `library/onda.json`,
- any live exercise of `basiliskus/data` PR #5, which was already reviewed and
  approved.

v0.2.0 and v0.3.0 each ended with a `chore: release` PR (#15, #20). v0.4.0
skipped it — the pipeline flow is next → run → retro, and the release was a
manual step nobody was prompted for.

Beyond that: 16 open issues, 10 Action Tracker rows Open, and all five
`basiliskus/.dotfiles` findings closed upstream.

## Paths compared

| Path | Order | Effort | Risk |
|---|---|---|---|
| **A** Ship first, then contract | ship → #38 → correctness | XS+S+M | Releases with 10 hardware rows unverified |
| **B** Verify first, then ship | correctness → ship → #38 | M+XS+S | Round trip stays dark; partner repo waits |
| **C** Ship + polish | ship → polish → correctness | XS+M+M | #38's partner waits a full milestone |
| **D** Coverage-first | coverage → ship → correctness | L+XS+M | Needs an ADR; opposes the no-Robolectric stance |

## Recommendation

**A — ship first.** v0.4.0 delivered nothing until tagged, and a daily-driver
app that isn't installed fails its own purpose. Releasing converts three
impossible tasks into possible ones in one step, and #38's partner repo was
already blocked on a field only this repo can emit.

## Decision

**B — verify first.** Chosen over the recommendation: unwilling to put
unverified code on a daily-driver phone, even though a sideload release is
cheap to redo.

Clarification recorded at decision time: **B cannot mean "verify the hardware
rows first"** — that is circular, since M1/M5 need a build carrying song
capture, which only the release provides. B means the correctness fixes land
*before* the tag, so the release carries them.

Accepted cost: the capture round trip stays dark longer, `data` PR #5 remains
untestable, and #38 waits.

### Version decision

One tag, **v0.5.0**, carrying both the unreleased v0.4.0 milestone and the
correctness fixes. Nothing from v0.4.0 has ever been installed, so a v0.4.0 tag
would be superseded within minutes and Obtainium would show two updates for
what is, to the user, one.

### Directional change

**None.** No cluster in B overrides an active CLAUDE.md constraint, so no ADR is
drafted. Path D *would* have — closing the Compose gap needs Robolectric or
instrumented tests, against the harness's deliberate no-Robolectric stance. If
coverage is picked up later, it needs an ADR first.
